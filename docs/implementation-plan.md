## 1. ゲーム概要

六角形のマスで構成されたマップ上で、2つの陣営が交互にユニットを動かして戦う
ターン制の戦術シミュレーション。原作の面白さの核である

- **支援効果と包囲効果** — 隣接する味方から力を借り、敵の逃げ場を6方向すべて塞げば攻防を半減させる
- **施設は格納庫** — 工場・港・飛行場はユニットをしまっておける。奪えば中身ごと手に入る
- **ZOC** — 敵の隣に踏み込むとそこで移動終了。戦線が意味を持つ
- **地形** — 道路＜平地＜丘陵＜荒地＜山の順に、移動コストと防御力が揃って上がる

を維持しつつ、次の3点を本作の性格とする。

1. **詰将棋性の徹底** — 乱数を排し、AI も決定的にする。盤面は必ず読み切れる
2. **現代・沿岸戦** — 舞台を宇宙から現代の地球へ移し、海上戦力と揚陸を追加する
3. **デバイスを問わず遊べる** — PC でもスマートフォンでも同じ体験で遊べる

### 1.1 設計指針 — 詰将棋性を最優先する

本作の面白さの源泉は、**盤面を睨んで最適解を組み立てる**ことにある。
限られた戦力で、地形とサポートを使い、何手でどう崩すかを読む。運で勝つゲームにはしない。
以下は他のあらゆる判断に優先する設計原則であり、迷ったらここに立ち返る。

| 原則 | 具体的な帰結 |
| --- | --- |
| **乱数を一切使わない** | 戦闘ダメージは確定値。搬出先もプレイヤーが選ぶ。AI の思考にも乱数を入れない |
| **AI が決定的である** | 同じ局面では必ず同じ手を指す。だからマップが「解ける」問題になる |
| **盤面情報をすべて開示する** | 索敵（Fog of War）を導入しない。地形・ユニット・施設・施設の中身はすべて見える |
| **結果を完全に予測できる** | 攻撃前に与ダメージ・返しダメージを正確に表示する。読み違いは思考の誤りであって情報不足ではない |
| **戦力が有限である** | 生産を設けない。一手の損得が最後まで響く |
| **試行錯誤を許す** | 自ターン内は何度でもアンドゥでき、マップの最初からもやり直せる |
| **マップは問題として設計する** | ランダム生成しない。1面ごとに攻略の筋を持たせて手で作る |

> **索敵について**: 検討の結果、導入しない。情報を隠すと「読み」が「手探り」に変わり、
> 本作の芯である詰将棋性と正面から衝突するため。潜水艦の被発見制限（4.5）だけは
> 情報を隠す仕組みではなく「攻撃できる相手を限定するルール」として実装する。

### 1.2 世界観の扱い — 燃料と弾薬を持たない理屈

燃料・弾薬は**ルールとして導入しない**（概念が増えると読みの負荷が上がるため）。
ただし原作は宇宙が舞台ゆえに飛行燃料が不要という理屈が通っていたのに対し、
本作は現代の地球なので、同じ言い訳は使えない。そこで次のように整理する。

**盤上の駒は、個々の車両や機体ではなく「その区域を担当する部隊」を表す。**

- 航空ユニットの駒は、常空にいる1機ではなく、**基地から出撃と帰投を繰り返している航空隊**。
  したがって「燃料が尽きる」という状態は駒のスケールでは表現されない
- 燃料・弾薬・整備は、**飛行場・港・工場での修理**という形ですでに抽象化されている。
  損耗した部隊が施設に戻って戦力を回復するのは、補充と再出撃の総体を表す
- 同じ理屈で、地上ユニットの弾薬補給も戦力の回復に含まれる

つまり「補給が要らない世界」ではなく、「**補給の成否は戦力という1つの数字に畳み込まれている**」
という立て付けにする。これなら現代設定でも筋が通り、ルールは増えない。

### 原作からの主な変更点

| 観点 | 原作 | 本作 |
| --- | --- | --- |
| 舞台 | 月面・宇宙 | 現代〜近未来の地球（沿岸部を含む） |
| 地形 | 陸上中心 | 海洋・浅瀬・港・砂浜を追加 |
| ユニット | 陸・空中心 | 陸・空に加えて艦艇・潜水艦・揚陸、多脚戦車・通信妨害車・電磁砲を追加 |
| 修理 | なし | 自軍施設に留まると回復 |
| 輸送 | 限定的 | 装甲兵員輸送車/輸送機/揚陸艦による積載・揚陸を戦術要素として設計 |
| 索敵 | 全面可視 | 全面可視（同じ） |

## 3. アーキテクチャ

### 3.1 レイヤ構成

```
src/
├── core/          ゲームロジック（純粋・DOM 非依存・テスト対象の中心）
│   ├── hex.ts             ヘクス座標系と幾何計算
│   ├── types.ts           GameState / Unit / Tile などの型定義
│   ├── map.ts             マップ生成・タイル参照
│   ├── movement.ts        移動コスト・到達範囲・経路探索（ZOC 込み）
│   ├── combat.ts          戦闘計算（同時解決・支援効果・包囲効果）
│   ├── facility.ts        施設の占領・格納・搬出
│   ├── victory.ts         勝敗判定
│   ├── commands.ts        コマンド定義と検証
│   └── reducer.ts         reduce(state, command) => { state, events }
├── ai/            CPU 思考（core にのみ依存）
├── render/        Canvas 描画（core を読むだけ。state を書き換えない）
│   ├── camera.ts          パン・ズーム・座標変換
│   └── layers/            地形 / グリッド / ハイライト / ユニット / エフェクト
├── input/         Pointer Events の抽象化（タップ・ドラッグ・ピンチ・ホバー）
├── ui/            画面遷移・パネル・レスポンシブレイアウト
├── data/          JSON ローダとスキーマ検証
├── editor/        マップエディタ（別エントリポイント）
└── main.ts

data/
├── units.json      ユニット性能表
├── terrain.json    地形定義
└── maps/*.json     マップデータ
```

**依存の向き**: `ui → input / render → core`、`ui → ai → core`。core は他を一切参照しない。
この分離により、core だけをヘッドレスで走らせて AI 同士の自動対戦テストが行える。

### 3.2 状態更新モデル（コマンドパターン）

すべてのプレイヤー操作・AI 操作を **Command** として表現し、単一の reducer で状態を更新する。

```ts
type Command =
  | { type: 'move';    unitId: UnitId; path: Hex[] }
  | { type: 'attack';  unitId: UnitId; targetId: UnitId }
  | { type: 'capture'; unitId: UnitId }
  | { type: 'load';    unitId: UnitId; carrierId: UnitId }
  | { type: 'unload';  carrierId: UnitId; unitId: UnitId; to: Hex }
  | { type: 'wait';    unitId: UnitId }
  | { type: 'endTurn' };

function reduce(state: GameState, cmd: Command): { state: GameState; events: GameEvent[] };
```

`events`（`unitMoved` / `unitDamaged` / `unitDestroyed` / `facilityCaptured` …）は
描画・アニメーション・効果音のトリガとして使い、core は描画を知らない。

この設計により以下が自然に得られる。

- **アンドゥ**: 状態のスナップショット、またはコマンド列の再生
- **リプレイ**: 乱数なし・決定的なので「初期状態 + コマンド列」で完全再現
- **AI の先読み**: AI が仮想的に reduce を回して手を評価できる
- **セーブ/ロード**: GameState を JSON 化して localStorage へ

## 4. ゲームルール仕様

> 本章の数値はすべて JSON の定数として外に出し、コード変更なしで調整できるようにする。
> 「原作準拠」と書いた箇所も、実プレイでの検証を経て第9章のバランス調整フェーズで確定させる。

### 4.1 座標系

- **フラットトップ（左右に頂点、上下が平ら）の六角形**を、列ごとに縦方向へずらして配置。
  近隣は N / S / NE / SE / NW / SW の6方向。
- **保存形式**: マップ JSON は人間が読める `odd-q` オフセット座標（列・行の二次元配列）。
- **内部計算**: 読み込み直後に軸座標 (q, r) へ変換。距離・近隣・範囲計算はキューブ座標で行う。

```
軸座標への変換: q = col,  r = row - (col - (col & 1)) / 2
距離: (|dq| + |dq + dr| + |dr|) / 2
```

### 4.2 ターン進行

1. **ターン開始フェーズ**
   - 再装填中のユニットの状態を解除する
   - 全ユニットの行動済みフラグをリセット
2. **操作フェーズ** — ユニットごとに「移動 → 攻撃 / 占領 / 積載 / 待機」を1回ずつ実行
3. **ターン終了** — 勝敗判定 → 相手プレイヤーへ

ユニットは1ターンに **移動1回 ＋ 行動1回**。攻撃・占領を行うと行動終了。
移動せずにその場で攻撃することも可能。

例外が2つある。**間接砲は移動したターンには攻撃できず**、
**バギー系は攻撃したあとにもう一度移動できる**（第5.1章）。

### 4.3 移動

- ユニットは **移動力（MP）** を持ち、進入するヘクスの移動コストを支払う
- コストは **地形 × 移動タイプ** の表で決まる（`terrain.json`）
- 移動タイプは**6種だけ**。地形コスト表（第5.2章）がすべての地形適性の根拠になる

| 移動タイプ | 該当ユニット | 通れる上限 |
| --- | --- | --- |
| `foot` | 歩兵、重歩兵、多脚戦車 | **山岳まで。すべての地形を通れる** |
| `track` | バギー、間接バギー、戦車6種、自走砲、対空戦車 | **荒地・湿地まで。山岳には登れない** |
| `wheel` | バイク兵、装甲兵員輸送車、ロケット砲、対空ミサイル車、通信妨害車 | **丘陵・森林・市街地まで。荒地から先へは進めない** |
| `air` | 戦闘機、攻撃機、輸送機 | 地形を無視して1で進む。**代わりに地形効果を受けられない** |
| `ship` | 水上艦 | 外洋・浅瀬・河川・港のみ |
| `sub` | 潜水艦 | 外洋のみ |

- 重砲と地雷は移動力0で、移動タイプを持たない
- **山岳に立てる装甲は多脚戦車だけ**。他の戦車は移動力に関係なく登れない

#### 進入できるかどうかは2つのルールだけで決まる

1. **地形表のコストが `−` なら進入できない**（車両は山岳に登れない、地上ユニットは外洋に出られない）
2. **コストがそのユニットの総移動力を超える地形には進入できない**

ユニットごとの個別制限は設けない。

| 例 | 移動タイプ / 総移動力 | 結果 |
| --- | --- | --- |
| 歩兵 | foot / 3 | どこへでも行ける。丘陵まで1、荒地・山岳・河川も2で越える |
| 重歩兵 | foot / 2 | 移動力2でも山岳（2）に登れる |
| 多脚戦車 | foot / 4 | **山岳に立てる唯一の装甲** |
| 主力戦車 | track / 6 | 荒地・浅瀬まで。山岳は移動タイプが通さない |
| 突撃戦車・重装戦車 | track / 4 | 荒地まで。上限は山ではなく荒地 |
| 要塞戦車 | track / 2 | **荒地（3）にも入れない**。移動力2ではコスト3を払えないという計算結果 |
| バイク兵 | wheel / 9 | 道路なら9ヘクス、平地では4ヘクス。荒地から先はタイヤが通さない |

要塞戦車が悪路に入れないのは「重装甲だから」という個別ルールではなく、
**単純に移動力2ではコスト3を払えないから**である。

- 経路探索は移動コスト付きダイクストラ。到達可能ヘクスをハイライト表示
- 味方ユニットのいるヘクスは**通過可能・停止不可**。敵ユニットのいるヘクスは通過不可
#### ZOC（支配地域）

敵ユニットに隣接するヘクスを **ZOC ヘクス**と呼ぶ。ルールは一つだけ。

> **移動経路上で、ZOC ヘクスへ連続して進入することはできない。**
> ZOC ヘクスに入った次は、必ず ZOC 外のヘクスへ出なければならない。
> 出られる先がなければ、そこで移動終了となる。

- 移動開始時点で ZOC ヘクスにいる場合、そこから出る1歩は「連続進入」に当たらず通常どおり動ける
- **攻撃を挟むと移動区間が切れ、連続進入の判定はリセットされる。**
  これによりバギー系だけが1ターンで ZOC ヘクスを2つ通過できる（第5.1章）
- 航空ユニットは ZOC の影響を受けない（原作準拠）
- ZOC を発生させるのは地上/海上ユニットのみ
- 盤面が全公開なので、ZOC による停止位置は移動前に完全に予測できる。
  経路プレビューに停止点を明示する

**なぜ「停止」ではなく「連続進入の禁止」なのか**

- **戦線を張った側の防御は保たれる。** 密に並べた線の周囲は ZOC ヘクスが連続するため、
  貫通するには必ず2連続で進入することになり、通れない
- 一方、**単独の敵の脇をかすめて通り過ぎる程度は許される**。
  これは戦線の突破ではなく単なる迂回であり、止める理由がない
- そして**バギーの攻撃後移動が、例外規定なしにそのまま成立する**。
  ZOC ヘクスへ踏み込んで殴り、ZOC 外へ抜ける動きが一般ルールの範囲内に収まる

### 4.4 戦闘（戦力10制・決定的）

各ユニットは **戦力 S**（初期値 10、0 で撃破）を持つ。戦力は攻撃力・被ダメージ量の両方に効く。
**乱数は使わない**ため、ダメージ予測を UI に常時表示でき、AI も正確に読める。

#### ダメージ計算

戦闘の解決は次の手順で行う。

```
1. 双方の「効果攻撃力 A」と「効果防御力 D」を求める

   A = 基礎攻撃力 × 戦力比 × expMul
       + Σ（隣接する自軍ユニットの 基礎攻撃力 × 戦力比）× SUPPORT_RATE

   D = DEF + Σ（隣接する自軍ユニットの DEF）× SUPPORT_RATE

   基礎攻撃力 = 目標が航空機なら power.air
                そうでなければ power.ground × matchup[目標の耐性クラス]

2. 包囲されている側は A と D の両方を半減する（× ENCIRCLE_MUL）

3. ダメージを算出する

   ダメージ = A_攻撃側 ÷ ( D_防御側 × terrainDef[防御側の地形] ) × DAMAGE_SCALE
```

```
SUPPORT_RATE  = 0.25   // 隣接する味方から借りられる割合
ENCIRCLE_MUL  = 0.5    // 包囲されたときの倍率
DAMAGE_SCALE  = 0.6    // 全体のテンポを決める定数
COUNTER_COEF  = 0.7    // 返しダメージに掛かる係数
expMul(lv)    = 1 + 0.10 × lv   // 熟練度。Lv0-2 → 最大 1.20
```

計算結果は四捨五入し、**1 以上・防御側の残存戦力以下**に丸める。

##### 対地と対空を別の値にする理由（原作準拠）

原作は各ユニットに **対地攻撃力と対空攻撃力を独立した2値**として持たせていた。
対空車両シーカーは対地30・対空65で、その比は 2.2 倍にもなる。

本作の `matchup`（相性）は 1.64 倍に収める制約があるため、
この差を相性では表現できない。したがって**原作と同じく2値に分ける**。

##### 各項が何を表しているか

| 項 | 役割 |
| --- | --- |
| `power.ground` / `power.air` | そのユニットの**基礎火力＝格**。原作の攻撃力を 1/5 に縮めた値（2〜18） |
| `matchup` | 地上・海上目標の中での**得手不得手**。得意 1.15 〜 苦手 0.70 |
| `戦力比` | **残存戦力に比例して火力が落ちる**。戦力5なら火力は半分。原作の「一隊すべての攻撃力を合算する」方式に対応する |
| `SUPPORT_RATE` | 隣接する味方から借りる割合。**借りる量は相手ユニットの強さに比例する**（第4.4章「支援効果」） |
| `ENCIRCLE_MUL` | 包囲されたときの倍率。攻防ともに半減する |
| `expMul` | 熟練度。**攻撃側にのみ効き、防御には影響しない** |
| `DEF` ÷ | ユニット固有の硬さ。**掛けるのではなく割る**（次項が重要） |
| `terrainDef` ÷ | 地形の防御補正。航空ユニットは常に 1.0 |
| `DAMAGE_SCALE` | 全体の削れ具合。大きいほど短期決戦になる |

##### 防御を「割合」にしない理由 — 原作からの明確な変更点

原作の防御力は **100% のうち何割かという減衰率**で、そこに地形効果とサポート効果が
**加算**される方式だった。このため合計が 100% に届くと**完全な無敵**が成立する。
防御力80のギガントが丘陵（+20%）に登るだけで、誰にも傷つけられなくなる。

無敵状態が存在すること自体よりも、**ハメ手のように簡単に到達できてしまう**ことが問題だった。

本作では防御を**除数**として扱う。原作の防御力 D は次の式で読み替えている。

```
DEF = 100 ÷ (100 − D)

  例: ムンクス（D=4）  → 1.04
      バイソン（D=40） → 1.67
      ギガント（D=80） → 5.00
```

被ダメージの比率は原作と同じに保たれるが、**割り算である以上 0 には収束しない**。
さらに**ダメージの下限を 1 とする**ため、
**無敵になる組み合わせは原理的に存在しない**。

```
最も硬い状態: 要塞戦車（DEF 5.0）が丘陵に立ち、隣接5体の重装戦車（DEF 2.5）に支援される
  D = 5.0 + 2.5 × 0.25 × 5 = 8.13   × 地形 1.2 = 9.75

そこへ最も強い攻撃: 突撃戦車が隣接5体の突撃戦車に支援されて攻撃
  A = 16.1 × (1 + 0.25 × 5) = 36.2

  ダメージ = 36.2 ÷ 9.75 × 0.6 = 2.2 → 2
```

最硬の状態でも必ず削れる。これが本作における「硬さの上限」になる。

#### 支援効果と包囲効果（本作の核）

原作にはこの2つが**別々の仕組み**として存在した。効果も、成立に必要な配置も違う。

| | 支援効果 | 包囲効果 |
| --- | --- | --- |
| **どこを見るか** | **自分に隣接する自軍**ユニット | **相手に隣接する6ヘクスすべて** |
| **効果** | 隣接ユニットの力を借りて自分が強くなる | 相手の攻撃力・防御力が**半減**する |
| **段階** | 隣接1体ごとに加算（連続的） | **全て埋めて初めて発動**（全か無か） |
| **借りる量** | 支援する側の攻撃力・防御力に**比例** | — |

##### 支援効果 — 力を借りる

**隣接する自軍ユニットの力を、その一部だけ借りられる。**
借りる対象は、自分が今どちらの役回りかで変わる。

- **攻撃するとき** … 隣接する自軍の**攻撃力**を借りる
- **攻撃を受けるとき** … 隣接する自軍の**防御力**を借りる

```
A = 自分の基礎攻撃力 × 戦力比 × expMul
    + Σ（隣接する自軍の 基礎攻撃力 × 戦力比）× 0.25

D = 自分の DEF
    + Σ（隣接する自軍の DEF）× 0.25
```

一律の割合ではなく、**支援する側の強さがそのまま効く**のが重要な点。
重装戦車を隣に置けば厚い盾になり、突撃戦車を隣に置けば鋭い矛になる。
**どの駒を隣に置くかが問われる。**

ここから自然に導かれる性質がいくつかある。

- **その目標を攻撃できない駒は、攻撃支援に寄与しない。**
  対空ミサイル車は地上目標への `matchup` が 0 なので、地上戦の攻撃支援では何も足せない。
  一方、防御支援には自分の DEF がそのまま効くので役に立つ
- **損耗した駒は支援も弱い。** 攻撃支援には戦力比が掛かる
- 支援できるのは最大5体（隣接6ヘクスのうち1つは戦闘相手が占めているため）。
  倍率の上限は `1 + 0.25 × 5 = 2.25 倍`

##### 包囲効果 — 逃げ場を奪う

**対象ユニットに隣接する6ヘクスすべてを自軍で埋めると、
その対象の攻撃力・防御力がともに半減する。**

- **全か無か**の効果。5ヘクスまで埋めても何も起こらず、6ヘクス目で一気に決まる
- **盤外のヘクス、および対象ユニットが進入できない地形のヘクスは「埋まっている」と見なす。**
  包囲とは逃げ場のない状態を指すので、そもそも逃げられない方向は塞ぐ必要がない。
  結果として、**敵を山や海に押し付けてから包囲する**のが最も効率的な手になる
- **地雷も包囲のヘクスを埋められる。** 攻撃力を持たない設置物が包囲を完成させるという、
  原作で地雷が主に包囲有利のために使われていたのと同じ形になる
- 攻撃力も半減するため、包囲された側は**反撃も弱くなる**

半減は非常に大きい。防御が半分になれば被ダメージは倍、攻撃も半分なので返しは半減する。
**6体を1体に投じる価値がある**、というのが本作の戦闘の骨格になる。

##### 2つが噛み合うと何が起きるか

包囲を完成させる6体のうち、実際に攻撃するのは1体。
残る5体のうち**攻撃側ユニットに隣接しているものは、そのまま支援にもなる**。
つまり包囲網の形によって、支援の乗り方まで変わる。

```
例: 要塞戦車（DEF 5.0）を突撃戦車（基礎攻撃力 16.1）で平地から殴る

  何もしない        16.1 ÷ 5.00 × 0.6 = 1.9  → 2 ダメージ
  包囲だけ成立      16.1 ÷ 2.50 × 0.6 = 3.9  → 4 ダメージ
  包囲＋支援2体     24.2 ÷ 2.50 × 0.6 = 5.8  → 6 ダメージ
```

**同じ駒で殴っても、配置次第で被害が3倍変わる。**
これが「工夫次第で相性を覆せる」という設計指針の実体になる。

#### 戦闘は同時に解決する

ターン制であっても、**1回の戦闘は攻撃側と防御側が同時に撃ち合うものとして解決する**。
「攻撃してから反撃される」という順次処理にすると、先に手を出した側が一方的に得をし、
戦闘前の盤面から結果を読むことも難しくなる。

```
1. 戦闘前の状態（両者の戦力・サポート数・熟練度・地形）から、
   攻撃側の与ダメージ D_atk と防御側の返しダメージ D_def を「両方先に」計算する
2. 計算が終わってから、両方を同時に適用する
       S_defender -= D_atk
       S_attacker -= D_def
3. 戦力が 0 になったユニットを戦闘解決後にまとめて取り除く
```

どちらのダメージも戦闘前の値だけで決まるため、**適用順序による差が原理的に生じない**。
相打ちは起こり得るが、返しダメージは防御側の戦闘前戦力に比例するため、
弱った敵にとどめを刺すときの反撃はごく小さくなる（戦力1なら通常の1/10）。

`D_def` は `D_atk` と同じ式を攻守入れ替えて計算し、**反撃係数 `COUNTER_COEF`（既定 0.7）**
を掛ける。攻撃を仕掛ける側に主導権の利を与えるための係数で、調整対象とする。

**返しダメージが発生しない条件** — すべて「防御側が攻撃側を攻撃できるか」だけで決まる。

- 防御側の射程が攻撃側の位置に届いていない
  （間接砲は最小射程2のため隣接には撃てず、射程1の駒は遠距離攻撃に反撃できない）
- 防御側の ATK 表で、攻撃側の耐性クラスに対する値が `0`
  （対空を持たない駒は航空機に反撃できない）
- 攻撃側が `noCounter: true`（届かない位置から攻撃する駒。現行ロスターでは未使用だが、将来の拡張のために枠を持たせる）

#### 間接攻撃ユニットの共通ルール

- 移動した turn には攻撃できない（移動か攻撃かを選ぶ）
- 最小射程が 2 以上のため、隣接した敵を攻撃できない
- 射程外から撃つため、原則として返しダメージを受けない

#### 熟練度（経験値）

生き残って戦い続けた部隊が精強になっていく感触を出す。**マップ内でのみ有効**で、
次のマップへは一切持ち越さない（各マップが独立した問題であり続けるため）。

| レベル | 呼称 | 必要経験値 | 攻撃倍率 |
| --- | --- | --- | --- |
| 0 | 新兵 | 0 | 1.00 |
| 1 | 古参 | 3 | 1.10 |
| 2 | 精鋭 | 8 | 1.20 |

- 経験値の獲得は**固定値**（乱数なし）。攻撃を行う: +1 / 敵を撃破する: +2（合計 +3）／
  返しダメージを与えた: +1
- **攻撃力にのみ効き、防御力・移動力には影響しない**
- マップ開始時に施設へ格納されているユニットは新兵（Lv0）。格納した部隊は熟練度を保つ
- 修理しても経験値は失われない（部隊は同一と見なす）
- 上限を +20% に抑えるのは、熟練部隊が一方的に無双する雪だるまを防ぐため。
  この幅なら支援（最大2.25倍）と包囲（2.00倍）で十分に覆せる

この仕組みは「**どのユニットにトドメを譲るか**」という新しい判断を生む。
主力を育てるか、戦力を温存するか、が毎回の攻撃で問われるようになる。
すべて決定的な固定値なので、何手先の熟練度も正確に読める。

#### 相性の強度に関する制約（重要）

「工夫次第で相性を覆せる余地を残す」ため、`matchup` の値域を5段階に固定する。
**これは地上・海上目標に対してのみ適用され、航空目標には `power.air` を直接使う。**

| 記号 | 値 | 意味 |
| --- | --- | --- |
| ◎ | 1.15 | 得意 |
| ○ | 1.00 | 標準 |
| △ | 0.85 | 不利 |
| ▲ | 0.70 | 苦手 |
| − | 0 | **攻撃不可**。構造的に成立しない組み合わせ |

得意と苦手の比は 1.15 ÷ 0.70 = **1.64 倍**で、制約の 1.8 倍以内に自動的に収まる。
これに対しプレイヤーが操作できる要素は
支援 2.25 × 包囲 2.00 × 地形 1.40 = **6.30 倍**（熟練度を含めれば 7.56 倍）。

**配置で作れる差のほうが、相性の差よりはるかに大きい。**
相性で負けていても、支援を集め、包囲を完成させ、地形を取れば覆せる。

#### power と matchup を分ける理由

`matchup` が「**誰に強いか**」、`power` が「**そもそもどれだけ強いか**」を担う。

この2軸を分けておかないと、「格上のユニット」を表現しようとするたびに相性の幅が広がり、
1.64 倍の枠が壊れてしまう。要塞戦車が突撃戦車より強いのは相性の問題ではなく格の問題で、
`power.ground` 18 対 14 として表す。相性表はどちらも「対装甲◎」のまま揃う。

### 4.5 潜水艦の扱い

索敵を導入しないため、潜水艦は「隠れる」のではなく **「攻撃できる相手を限定する」** ルールで表現する。

- 潜水艦の位置は常に見える（盤面は全公開）
- ただし **`canDetectSub: true` を持つのは駆逐艦と潜水艦だけ。他のいかなるユニットも
  潜水艦を攻撃できない**。水上艦から見た回答は駆逐艦1種のままで、
  相性も駆逐艦 ◎ に対し潜水艦 △ なので、対潜の主役は駆逐艦になる
- 潜水艦自身は水上艦・輸送船を強力に攻撃できる

これにより「潜水艦に対処できる駒を戦線のどこに置くか」という**手駒の配置問題**になり、
情報を隠すことなく潜水艦らしさを出せる。読み切れる範囲に収まるため詰将棋性を損なわない。

**航空機からの対潜攻撃は行わない。** 攻撃機が潜水艦を撃てるとすると、
「対潜を持つ駒をどこに置くか」という問題が、制空権を取るだけで解けてしまう。
潜水艦への回答を駆逐艦1種に絞ることで、艦隊編成そのものが問われるようになる。

> **マップ設計上の制約**: 潜水艦を配置するマップには、
> 相手側にも必ず駆逐艦を用意する。回答のない駒を置いてはならない。

### 4.6 施設・格納・搬出（生産なし）

| 施設 | 効果 |
| --- | --- |
| 司令部（HQ） | 陣営の本拠地。占領されると敗北。地上ユニットの修理 |
| 工場 | **地上ユニットの格納庫**。格納で修理も兼ねる |
| 港 | **海上ユニットの格納庫**・修理 |
| 飛行場 | **航空ユニットの格納庫**・修理 |

#### 生産は存在しない

資源やお金を貯めてユニットを作る仕組みは**設けない**。ユニットの供給源は次の2つのみ。

1. マップの初期配置
2. マップ JSON に定義された、施設ごとの**中身（格納されているユニット）**

これにより、各マップの戦力配分は完全にマップ設計者がコントロールできる。
プレイヤーは「限られた戦力をいかに損耗させずに使うか」を考えることになり、
修理拠点の確保と部隊の引き際が重要な判断になる。

#### 占領と施設ヘクスへの進入制限

- 占領は**歩兵系（`canCapture: true` を持つ歩兵・重歩兵・バイク兵）のみ**が実行できる。
  施設ヘクスに乗り `capture` を実行する。占領は1ターンで完了する
- **未占領（中立または敵）の施設ヘクスには、占領できるユニットしか進入できない。**
  戦車も艦艇も航空機も、敵の工場の上に乗ることはできない
- 自軍が占領済みの施設ヘクスには、その施設に対応する種別のユニットが進入できる（修理のため）

この制限により、**施設の争奪は必ず歩兵の仕事**になる。
戦車部隊だけで攻め込んでも工場は落とせず、歩兵をどう前線まで届けるかが計画の骨格になる。

#### 施設は生産設備ではなく格納庫

資源を貯めてユニットを作る仕組みが無いのと同じく、**施設が自動でユニットを吐き出すこともない。**
施設にできるのは、ユニットを**しまう（格納）**ことと、**出す（搬出）**ことだけ。

- マップ JSON の施設は「開始時点で中に入っているユニット」を持つ
- **収容数に上限はない**
- 中身は自動では出てこない。所有している陣営が `deploy` で1体ずつ出す
- 出し切ったら空になる。そこから増えることはない
- **敵味方を問わず、全施設の中身はいつでも参照できる**。
  「あの工場には戦車が眠っている」という読みを成立させるため

#### 格納

- 自軍が所有する施設ヘクスに乗ったユニットは、`store` で中へ入れる
- 格納したユニットは**盤上から消える**。攻撃も支援も包囲も受けない
- 中に入った時点で**戦力が 10 に全快する**
- **熟練度は失われない**。同一の部隊が補充を受けたものと見なす
- 格納した時点で行動終了。**そのターンには搬出できない**

#### 搬出

- `deploy` で、施設の**隣接する空きヘクス**へ全快の状態で出す
- **搬出したターンは行動終了**。動かせるのは次のターンから
- **隣接ヘクスがすべて塞がっていれば1体も出せない。**
  つまり**敵工場の周囲を自軍ユニットで固めて中身を閉じ込める**のが有効な戦術になる
  （工場ヘクス自体には歩兵しか入れないため、包囲する側は周囲を固めることになる）
- 出す先はプレイヤーが選ぶ。AI は走査順を固定するので、同じ局面なら必ず同じ搬出になる

#### 修理は格納の副作用（即時全快）

回復量ではなく、**格納と搬出の往復そのもの**が修理のコストになる。

```
ターンN   : 施設へ入り格納（行動終了）。中で全快する
ターンN+1 : 隣接ヘクスへ搬出（行動終了）
ターンN+2 : ようやく動かせる
```

前線を離れて施設まで戻る移動に加えて、この**2ターンの出し入れ**がかかる。
それだけの時間を払わせるので、回復は段階的（毎ターン +3 など）にせず**即時全快**でよい。

- 施設の種別と受け入れられるユニットは上表のとおり（工場に艦艇は入れないので自然に分かれる）
- 修理のみで、弾薬・燃料といった補給の概念は導入しない（第1.2章）

#### 占領されると中身ごと相手のものになる

**施設そのものは攻撃できない。** 中に格納したユニットが撃破されることはない。
そのかわり、施設を占領されると**中身はそのまま新しい所有者のものになる**。
奪ったその場では出せず、搬出できるのは次のターンから。

前線の施設に部隊を預けるのは、それ自体が賭けになる。

### 4.7 輸送・積載（海洋要素の中核）

積載枠を持つのは **装甲兵員輸送車 / 輸送機 / 揚陸艦** の3種。それぞれ運べる対象と
降ろせる場所が異なり、役割が重ならないようにする。

| ユニット | 積載 | 降ろせる場所 |
| --- | --- | --- |
| 装甲兵員輸送車 | 歩兵2 | 平地・道路・荒地・砂浜 |
| 輸送機 | 歩兵2 **または車両1**（重砲を含む） | 平地・道路・砂浜・飛行場 |
| 揚陸艦 | 地上ユニット3（重砲を含む） | 砂浜・港（隣接する浅瀬から揚陸する） |

#### 展開可能地形という共通ルール

**積荷を降ろせるのは段階0と段階1の地形（道路・橋・施設・平地・砂浜）に限る。**
これはすべての輸送ユニットに共通する制約で、
丘陵・森林・市街地・荒地・湿地・山岳には、どの輸送手段を使っても直接降ろせない。

- 山越えで戦車を送り込みたければ、山の向こう側にある平地を確保しておく必要がある
- 上陸したければ砂浜か港が要る。断崖に張り付いた海岸線は上陸できない
- **降ろせる場所が限られること自体が、マップ設計の道具になる**。
  どこに展開適地を置くかで、攻撃側の選択肢を設計者が制御できる

- 積載中のユニットは行動できず、輸送ユニットが撃破されると同時に失われる
- 降ろされたユニットはそのターン行動済み（強襲上陸・空挺降下を強すぎなくするため）
- 輸送機が車両を運べるため、**山脈で隔てられた戦域へ戦車を送り込む**という選択肢が生まれる。
  ただし降ろせる地形が限られるので、着陸適地の確保が前提になる

盤面が全公開なので、揚陸は「気づかれずに回り込む」奇襲ではなく、
**「何ターンで着くか、その間に阻止されるか」を互いに読み合う速度勝負**になる。
これは詰将棋的な設計とよく噛み合う。

#### 歩兵とバイク兵 — 踏破力と速度の対立

占領できる駒は3種あり、**地形との関係がそれぞれ正反対**になっている。

| | 移動力 | 地形適性 | 性格 |
| --- | ---: | --- | --- |
| 歩兵 | 3 | **どこへでも行ける**（丘陵まで1、荒地・山岳・湿地も2） | 遅いが地形に阻まれない |
| 重歩兵 | 2 | 同上 | 最も遅いが装甲と撃ち合える |
| バイク兵 | **9** | **道路1／平地2／丘陵3／荒地以降は進入不可** | 道路の上でだけ本領を発揮する |

バイク兵の移動力9は、**道路が繋がっている場合にのみ**9ヘクス分の意味を持つ。
平地では実質4〜5ヘクス、荒地に入った時点で足が止まる。

この対比によって、**マップ上の道路網が戦略的な資産になる**。
道が通っている方向へはバイク兵が一気に届き、道が途切れた先へは歩兵が地道に歩く。
どちらの経路で施設を取りに行くかが、そのままマップの読み筋になる。

#### 攻撃後の移動 — バギーを唯一の存在にする仕組み

通常のユニットは「移動 → 攻撃」で行動を終える。
バギー系（`attackDuringMove: true`）はそうではなく、
**移動と攻撃が一続きの行動になっていて、移動経路の任意の地点で1回だけ攻撃を挟める**。

```
通常ユニット:   移動（MP消費） → 攻撃 → 行動終了
バギー系:       移動 …… 任意の地点で攻撃 …… 残った MP で移動を続行
```

- 攻撃する場所は**どこでもよい**。移動を始める前（開始位置）でも、経路の途中でも、
  移動を終えた地点でもよい。**開始位置の射程内に敵がいれば、撃ってから全力で動ける**
- **移動力を使い切っていれば、攻撃後は動けない。** 攻撃後に動けるのは残 MP のぶんだけで、
  「攻撃したら必ずもう一度動ける」わけではない
- 攻撃は1回まで。移動の途中で複数回撃つことはできない

#### 攻撃を挟むと ZOC の判定が切れる

**攻撃を境に移動は2つの区間に分かれ、ZOC の連続進入判定は区間ごとに行う。**

```
区間1: 移動 …… ZOC ヘクス A へ進入（区間1の1回目）
        ↓
      攻撃 …… ここで区間が切れ、連続進入の判定がリセットされる
        ↓
区間2: 移動 …… ZOC ヘクス B へ進入（区間2の1回目なので可能）
```

結果として、**バギーだけが1ターンで ZOC ヘクスを2つ通過できる**。
他のどの駒も移動区間を1つしか持たないため、ZOC ヘクスは1つまでしか通れない。

これが「殴ってから逃げる」以上に大きい、バギーの本質である。
**本来なら踏み込めない敵陣の裏へ、攻撃を足がかりにして無理やり回り込める。**
戦線に穴が空いていなくても、殴ることで一時的に道をこじ開けられる。

- 間接バギーは射程2から撃てるため、ZOC の外から殴ってさらに踏み込む形も取れる

これは他のどの駒でも代替できない性質で、間接砲の「移動したターンは撃てない」制約の
ちょうど裏返しになっている。片方は撃つために止まり、もう片方は撃ってから逃げる。

代償として**装甲は全ユニット中で最も薄い**。捕まれば一撃で溶ける。
火力は突撃戦車と同格（対地 power 14）でありながら、防御は 1.25 と戦車の半分程度しかない。
**当てる力は最強クラス、耐える力は最低クラス**という極端な駒になる。

#### 捨て身の挟み撃ち

バギーは足の速さで、本来なら届かない位置の ZOC ヘクスへ1手でねじ込める。
包囲効果は**6ヘクスすべてが埋まって初めて発動する全か無かの効果**なので、
最後の1ヘクスを埋められるかどうかで結果が劇的に変わる。
撃破されることを承知でバギーを差し込んで包囲を完成させ、
次の一手で本命の攻撃を通す、という使い方ができる。

戦力を捨てて配置を取る。これが意味を持つのは、生産がなく一手の重みが大きい本作ならではで、
バギーは「速いだけの駒」ではなく**盤面を作りにいく駒**になる。

#### 重砲を「移動不可」にする理由

重砲は自力で1ヘクスも動けない。その代わり射程・火力ともに最強で、盤上に
**「そこには近寄れない」という線を引く**駒になる。

- 移動しないため、間接砲の「移動したターンは撃てない」制約に一切かからず、毎ターン撃てる
- 一度迂回されると何もできない。射線の外へ回り込む経路を見つけることが攻略の一部になる
- **輸送機（車両1枠）・揚陸艦でなら運搬できる**。自力では動けないが、運べば展開し直せる。
  これは輸送ユニットの価値を大きく引き上げる

移動力ゼロという極端な制約が、他のどの駒とも重ならない性格を作っている。

#### 地雷の仕様

原作の挙動に倣い、**地形ではなくユニットとして**扱う。この形なら新しいルールをほとんど
足さずに実装できる。

| 項目 | 仕様 |
| --- | --- |
| 移動力 | 0（自力では動けない） |
| 攻撃力 | 0（攻撃も返しダメージもしない） |
| ZOC | **通常どおり発生させる**（他のユニットと同じ） |
| 効果 | **敵ユニットは地雷のあるヘクスに進入できない** |
| 排除方法 | **攻撃して破壊する**。1ユニットの1ターンを消費させられる |
| 設置方法 | 輸送ユニットに積載して運び、**展開可能地形へ降ろす**ことで設置する |
| 設置できる場所 | 展開可能地形（平地・道路など）のみ。森林や山岳の隘路は塞げない |

**実装がほぼ既存ルールの再利用で済む**のが大きい。
「敵ユニットのいるヘクスは通過不可」「輸送の積載・展開」「移動力0の駒」は
すべて重砲と輸送のために既に用意されている仕組みで、地雷はその組み合わせでしかない。

戦術的には2つの働きをする。

1. **テンポを奪う** — 撃破に1手かかるため、敵の進軍を確実に1ターン遅らせられる
2. **包囲を完成させる** — 地雷もユニットである以上、**包囲効果の6ヘクスを埋められる**。
   攻撃力ゼロの駒が、置いてあるだけで相手の攻防を半減させる決め手になる
3. **味方を硬くする** — 地雷の DEF は 5.00 で全ユニット最硬。
   **隣接する味方はその 25% を防御支援として受け取る**（+1.25）。
   狙われやすい戦車の隣に置けば、弱い戦車が見違えるほど硬くなる。
   原作の防衛戦でよく使われた戦術がそのまま成立する

原作でも地雷は主に包囲有利を取るために使われていたとされ、この2点目こそが本命の用途に近い。

一方で設置できる地形が限られるので、狙った隘路をピンポイントで塞げるとは限らない
（この「思うようには置けない」感覚は原作と同じ）。

#### 相性の輪 — 対空戦車を要とする4すくみ

本作の相性設計の背骨。**対空戦車が地上攻撃力も持つ**ことで、陸と空をまたぐ輪が閉じる。

```
        戦車 ──────▶ 対空戦車
         ▲                │
         │                │
         │                ▼
        攻撃機 ◀────── 戦闘機

        ※ 攻撃機 と 対空戦車 は互角（攻め合いになる）
```

| 関係 | 理由 |
| --- | --- |
| 戦車 → 対空戦車 | 対空戦車は地上も撃てるが、装甲と火力で戦車に及ばない |
| 対空戦車 → 戦闘機 | 制空の主役も、地上から待ち構える対空砲火の前では落ちる |
| 戦闘機 → 攻撃機 | 対空を持たない攻撃機は、戦闘機に一方的に狩られる |
| 攻撃機 → 戦車 | 空からの対地攻撃に、戦車は反撃できない |
| 攻撃機 ⇔ 対空戦車 | **互角**。攻撃機は地上攻撃力を持つため、一方的にはならず撃ち合いになる |

この輪があるため、どの駒も「出しておけば強い」とはならない。
対空戦車を並べれば戦車に食われ、戦車を並べれば攻撃機に食われる。

#### 唯一の例外 — 要塞戦車

要塞戦車だけは対空を持つため、「攻撃機 → 戦車」の関係が成立しない。
**これは輪を壊す例外ではなく、輪の外に置いた攻城対象**として意図的に設けたもの。

正面から殴り合うと、どの駒で挑んでも割に合わない。

| 攻め手 | 与ダメージ | 返し | 判定 |
| --- | --- | --- | --- |
| 攻撃機 | 16.1 ÷ 5.00 × 0.6 = **1.9** | 8 ÷ 1.45 × 0.6 × 0.7 = 2.3 | **攻撃機のほうが損** |
| 突撃戦車 | 16.1 ÷ 5.00 × 0.6 = **1.9** | 20.7 ÷ 2.00 × 0.6 × 0.7 = 4.3 | **論外。2倍以上の差** |

正しい攻め方は3つある。

| 手 | 内容 |
| --- | --- |
| **① 包囲する** | 隣接6ヘクスをすべて自軍で埋め、要塞戦車の攻防を半減させる。突撃戦車で **与3.9 / 返し2.2** となり殴り勝てる。支援を2体分乗せれば与6まで伸びる。山や海に押し付ければ、埋めるべきヘクスは6より少なくて済む |
| **② 間接砲で削る** | 重砲 2.2 / 自走砲 1.2。遅いが**返しダメージを一切受けない**。移動力2の要塞戦車は間接砲を追いかけられない |
| **③ 無視する** | 移動力2で平地・道路・荒地・市街地しか進めない。振り切ってしまえば追ってこられず、盤面から実質的に退場させられる |

要塞戦車の答えは「殴り勝つ」ではなく「**包囲して弱らせる**」「**間接砲で崩す**」「**相手にしない**」。
相性の輪とは別種の、**攻城戦という問題**を盤上に持ち込む駒になる。
1体置かれるだけでマップの読み筋が変わるため、配置はマップ設計者が慎重に決める。

対空能力は `power.air 8` で、対空ミサイル車（17）の 47%。
原作のギガント40／ホークアイ85 と同じ比率にしてある。

#### 対空は近接と間接を1体ずつ揃える

対空を1種に絞ると、間接兵器の駆け引きが対空から失われてしまう。そこで**両方置く**。

| | 対空戦車（近接） | 対空ミサイル車（間接） |
| --- | --- | --- |
| 射程 | 1 | 2〜4 |
| 地上目標 | 撃てる（戦車には劣る） | **撃てない** |
| 移動後の攻撃 | 可 | 不可 |
| 弱点 | 戦車との正面戦闘 | **至近距離に踏み込まれると一方的に倒される** |
| 役割 | 相性の輪の要。部隊に随伴して空を拒否する | 拠点上空を広く覆う。単独では守れない |

間接兵器共通の性質として、**懐に入られると何もできない**。
対空ミサイル車は広い傘を張れるが、その傘を守る駒が要る。

加えて、対空能力は**専用ユニット以外にも薄く配る**。
歩兵は携行火器、駆逐艦とコルベットは艦載対空砲を持ち、航空機に対して小さいが 0 ではない
攻撃力を持つ。これにより「対空の駒がないから航空機に手も足も出ない」局面が生まれず、
それでいて**本気で空を止めるには対空戦車か戦闘機が要る**、という段差が残る。

#### 設計制約 3: 紛らわしい組み合わせは軸を分ける

役割が近い駒は、**どちらかが上位互換にならないよう軸を明確に分ける**。

| 組 | 分け方 |
| --- | --- |
| **戦車5種** | 主力戦車を基準に置き、**1つの能力を上げたら別の1つを下げる**形で派生させる。快速戦車＝機動↑防御↓、突撃戦車＝火力↑機動↓、重装戦車＝防御↑機動↓、多脚戦車＝踏破力↑機動↓。どれも基準の上位互換にならない |
| **突撃戦車 と 重装戦車** | 同じ重戦車枠だが、片方は殴る役、片方は殴られる役。突撃戦車で穴を開け、重装戦車で受け止める、という役割分担になる |
| **重装戦車 と 要塞戦車** | 重装戦車は移動力4で軍と一緒に動ける「動く盾」。要塞戦車は移動力2で開けた地形しか通れない「動かない要塞」。前者は前線を押し上げるために使い、後者は取った場所を渡さないために置く |
| **突撃戦車 と 要塞戦車** | 火力は同格だが、突撃戦車は移動力4で殴りに行けるのに対し、要塞戦車は事実上その場から動けない。**攻めの火力**と**守りの火力**で分かれる |
| **重装戦車 と 多脚戦車** | 重装戦車は「開けた地形限定で最も硬い」、多脚戦車は「どこでも行けるが火力も防御も並」。重装戦車が入れない森林・山岳・湿地こそ多脚戦車の主戦場 |
| **間接砲4種** | 機動と火力・射程を反比例させた一本の軸に並べる。**間接バギー**（射程2・最低火力・攻撃後移動）→ **自走砲**（射程2〜4・高火力）→ **ロケット砲**（射程3〜6・中火力）→ **重砲**（射程2〜8・最大火力・移動不可）。撃ってから逃げるか、動かずに撃ち続けるかの両極を端に置く |
| **バギー と 快速戦車** | どちらも速い駒だが、バギーは防御1.25・移動中攻撃で「捕まらないことで生き残る」。快速戦車は防御2.00・移動7で「殴られても耐える」。火力は同格なので、脆さと引き換えに何を得ているかで分かれる |
| **ミサイル巡洋艦 と 電磁砲艦** | 陸の「自走砲 と 重砲」と同じ関係を海に持ち込む。巡洋艦は毎ターン撃てる中火力、電磁砲艦は最大火力だが1ターンおき |
| **対空戦車 と 対空ミサイル車** | 前者は射程1で地上も撃て、移動後も攻撃できる随伴型。後者は射程2〜4で拠点を広く覆うが、地上に無力で、懐に入られると倒される |
| **歩兵 と 重歩兵** | 重歩兵は装甲と撃ち合えるが低速。歩兵は数を並べる速度と踏破力で勝る |

| **空輸の積載制限** | 航空機以外なら何でも運べる（1ユニット） | 地上兵器なら何でも運べ、**歩兵なら2ユニット**運べる | ✅ **本作のほうが緩い**。制限を強める必要はない |
| **山岳へ入れる駒** | 歩兵2種のみ | 歩兵2種 ＋ 多脚戦車 | 本作の追加要素として意図的 |
| **工兵の性格** | 「重装甲・高火力・低機動の歩兵」であり、地形を改変する駒ではない | 重歩兵がその役割を担う | ✅ 工兵を不採用にした判断は結果的に正しかった |
| **軽車両の対空** | ラビット・リンクスとも対空10を持つ | バギー・間接バギーとも対空 power 2 | ✅ 一致 |
| **航空機と地形** | 地形を無視して移動できるが、**地形効果（防御補正）も受けられない** | 同じ（航空の地形防御は一律1.0） | ✅ 一致 |

#### 戦車枠の拡張（第12版）

原作の戦車7種のうち、性格がはっきりしているものを参考に**3種→6種へ拡張**した。

| 原作の戦車 | 性格 | 本作での扱い |
| --- | --- | --- |
| バイソン | 量産型 | **主力戦車**として採用。すべての基準になる駒 |
| グリズリー | 攻撃力高めの重戦車 | **突撃戦車**として採用 |
| アルマジロ | 防御力高めの重戦車 | **重装戦車**として採用 |
| スラッガー | 移動力が高く多少の装甲もある中戦車 | **快速戦車**として採用 |
| レネット | 旧型戦車。原作でも存在感が薄い | 見送り。基準の駒と役割が重なるため |
| モンスター | 移動力が高めで攻撃力・防御力もバランスが良い重戦車 | **見送り**（下記の理由） |
| ギガント | 要塞戦車。移動力は歩兵以下だが作中最強の攻防を持ち、対空もそこそこある | **要塞戦車**として採用 |

**CPU 優遇ユニットを取り込まない理由**

モンスター、スラッガー、そして航空機のハンターは、**主に CPU 側が使う優遇ユニット**
だったとのことで、当時の思考ルーチンの弱さを戦力差で埋めるための設計だったと考えられる。
このうち性格が明確なスラッガーは快速戦車として採り、残る2種は見送る。

- **モンスター型**（移動も攻撃も防御も高い重戦車）は、他の戦車すべての上位互換になる。
  第5.1章の設計制約1「死に駒を作らない」に真正面から反する
- **ハンター型**（陸にも空にも対応でき、硬い汎用戦闘機）は、**相性の輪を壊す**。
  1機で制空と対地を兼ねてしまうと、戦闘機と攻撃機という2つのノードが1つに潰れ、
  戦車 → 対空戦車 → 戦闘機 → 攻撃機 → 戦車 の4すくみが閉じなくなる
- そもそも本作の AI は決定的で先読みを行う設計であり、手応えはマップ設計で作る方針のため、
  **AI を強く見せるための優遇ユニットを必要としない**

原作の設計思想を否定するものではなく、**AI の作り方が違うので必要な道具も違う**、という判断。

#### 残る論点

| 論点 | 内容 |
| --- | --- |
| **前線で修理する移動ユニット** | 修理は施設ヘクスのみ。原作にも該当する駒はなさそうなので、このままで問題ない見込み |

### 5.1.3 検討中の追加要素（案）

確定ロスターには含めていないが、**判断材料として並べておく**もの。
採用は全体のバランスを見て決めるため、確定した仕様とは同列に扱わない。

#### その他の案

| 案 | 内容 | 利点 | 懸念 |
| --- | --- | --- | --- |
| **無人戦闘車（UGV）** | 地上の近未来枠。返しダメージを受けない直接攻撃、あるいは一度だけ使える自爆突撃 | 無人兵器は地上兵器として扱うほうが素直 | 「反撃を受けない直接攻撃」は強すぎる可能性が高い。自爆は使い捨て概念の新規追加になる |
| **範囲攻撃** | 攻撃機などが対象と周囲1ヘクスに減衰ダメージを与える | 支援効果が促す「密集」に対して逆向きの力が働く | 航空をさらに強くしてしまう。見送り済み |
| **空母** | 航空ユニットの海上拠点。搭載と修理 | 沿岸マップで航空の運用範囲が広がる | 施設＝修理拠点という現行ルールと二重になる |
| **陣地構築** | 歩兵がその場に留まり続けると地形防御が上がる | 防御側に「待つ」という積極的な手ができる | 膠着を助長する |
| **橋の破壊** | 特定ユニットが橋を落として経路を遮断する | 地形の重みが増す | 地形が動くとマップを問題として設計しづらくなる |

> **バギーは第9版で確定ロスターへ昇格した**（近接・間接の2種）。
> 「攻撃後に移動できる」という他に代えのきかない特徴を持つため、案ではなく本採用としている。

### 5.2 地形（`data/terrain.json`）

原作は **道路・橋・施設 ＜ 平地 ＜ 丘地 ＜ 荒地 ＜ 山** の順に、
**移動コストと地形効果が揃って上がる**という単純な階段構造だった。本作もこれに倣う。

**地形効果は耐性クラスごとに変えない。1つの地形に1つの値。**

#### 地形表

| 段階 | 地形 | foot | track | wheel | 地形効果 |
| ---: | --- | ---: | ---: | ---: | ---: |
| 0 | 道路 / 橋 / 工場 / 司令部 / 港 / 飛行場 | 1 | 1 | 1 | 1.0 |
| 1 | 平地 / 砂浜 | 1 | 1 | **2** | 1.1 |
| 2 | 丘陵 / 森林 / 市街地 | 1 | 2 | **3** | 1.2 |
| 3 | 荒地 / 湿地 | 2 | 3 | **−** | 1.3 |
| 4 | 山岳 | 2 | **−** | **−** | 1.4 |
| 水 | 河川 / 浅瀬 | 2 | 4 | − | 1.0 |
| 水 | 外洋 | − | − | − | 1.0 |

- `air` はすべての地形をコスト1で通り、**地形効果は常に 1.0**（地形に守られない）
- `ship` は河川・浅瀬・外洋・港のみコスト1。`sub` は外洋のみ
- **歩兵は丘陵までコスト1**で歩き、荒地・山岳・河川も2で越える。遅いが地形を選ばない
- **車両（track）の上限は荒地・湿地。山岳には登れない**
- **タイヤ（wheel）は段階1から余分にコストを払い、荒地から先へは進めない**
- **マイナス倍率（1.0 未満）は設けない。** 地形は守ってくれるか、何もしないかのどちらか

#### この表から導かれること

- **道路網が戦略資産になる。** 段階0はどの移動タイプでもコスト1。
  タイヤ系は道路の上でだけ本来の速度を出せる
- **山岳は歩兵と多脚戦車だけの領域になる。** 装甲部隊が絶対に来られない場所があることで、
  歩兵が単なる占領要員以上の意味を持つ
- **要塞戦車（移動力2）は荒地にも入れない。** 個別ルールではなく、
  コスト3が総移動力2を超えるという計算結果
- **重歩兵は移動力2でも山岳に登れる。** 段階4のコストが2だから。
  最も遅い駒が最も険しい場所に立てるという逆転が生まれる

#### 施設ヘクスの扱い

工場・司令部・港・飛行場は段階0（コスト1・地形効果1.0）。
守りやすさではなく**占領対象としての価値**で設計された地形なので、
地形効果は与えない。守りたければ周囲の丘陵や森林に部隊を置くことになる。

  "name": "丘陵",
  "tier": 2,
  "moveCost": { "foot": 1, "track": 2, "wheel": 3, "air": 1, "ship": null, "sub": null },
  "defense": 1.2

読み込み時に**スキーマ検証**を行い、不正なマップは明示的なエラーで落とす

リリース前の必須作業は「**開発者が実際にそのマップをクリアできること**」の確認とする
（高難易度マップを作る場合に限り、想定手順を書き残す）。

## 6. AI 設計

`ai/types.ts` にインターフェースを切り、実装を差し替えられるようにする。

```ts
interface AiPlayer {
  planTurn(state: GameState, playerId: PlayerId): Command[];
}
```

### 決定性の要件（最重要）

第1.1章の指針により、**AI は完全に決定的でなければならない**。
同じ局面に対して常に同じ手を返すからこそ、マップが「解ける問題」になり、
プレイヤーは試行錯誤して最適解に到達できる。

- 乱数を一切使わない（`Math.random` は ESLint で禁止する）
- 同点の手は、ユニットID・座標などの**安定した基準で必ず同じ順序**に決める
- `Map` / `Set` の反復順（挿入順）に結果が依存しないようにする。
  評価対象は必ず明示的にソートしてから走査する
- この性質は自己対戦テストの再現性も担保する（バグを必ず再現できる）

### v1（MVP 用・貪欲）

各ユニットについて、実行可能な行動を列挙し、単純なスコアで最良手を選ぶ。

1. 攻撃可能な敵がいれば、`与ダメージ − 想定反撃ダメージ` が最大の攻撃を選ぶ
2. 占領可能な施設に乗れるなら占領
3. 戦力が半分以下なら自軍施設へ後退して修理
4. どれも無ければ、最も近い敵または未占領施設へ前進

盤面が全公開なので、v1 の時点でも「見えない敵にどう対処するか」を考える必要がなく、
実装は素直になる。

### v2（評価関数型）

盤面評価関数を定義し、1ターン分の行動順を貪欲＋局所探索で最適化する。

```
score = Σ(自軍ユニット戦力 × 種別価値) − Σ(敵軍ユニット戦力 × 種別価値)
      + W_facility × 占領施設数の差
      + W_hq       × 敵HQへの距離の逆数
      + W_support  × 支援優位（自軍ユニットが受けている支援量 − 敵のそれ）
      + W_encircle × 包囲の進捗（あと何ヘクスで包囲が成立するか。成立済みは特に高く）
      + W_terrain  × 各ユニットの地形防御ボーナス
      + W_threat   × 次ターンに敵から受けうる総ダメージ（負の重み）
```

- 行動順序（誰から動かすか）が結果を大きく変えるため、
  複数の順序を**決められた手順で**列挙し、最良のものを採る
- 相手の反撃は1手先まで読む（`reduce` を仮想実行してシミュレート）。
  乱数がないため、この読みは完全に正確になる
- **難易度選択は設けない。AI は常に1種類**で、全マップを同じ思考が担当する。
  手応えの差はマップ設計側で作る（難しいマップは戦力配分と地形でそう設計する）
- したがって「あえて最善を選ばない」ような弱体化処理も一切持たない

### 自己対戦テスト

ヘッドレスで AI 同士を数百戦させ、
- 例外・無限ループ・不正コマンド・膠着の検出
- マップごとの先手勝率（バランス指標）
を CI とは別のスクリプトで測定する。

## 7. UI / UX（マルチデバイス対応）

**PC・タブレット・スマートフォンのいずれでも同じゲームが快適に遊べること**を要件とする。
これは後付けが非常に高くつくため、Phase 2 の時点で入力抽象化とカメラを作り込む。

### 7.1 入力の抽象化

- **Pointer Events** に統一し、マウス・タッチ・ペンを1つのコードパスで処理する
- ジェスチャ層で `tap` / `longPress` / `drag` / `pinch` / `hover`（対応デバイスのみ）を解釈
- **ホバー前提の設計を禁止する**。ホバーでしか得られない情報を作らない

### 7.2 操作

| 操作 | PC | タッチ |
| --- | --- | --- |
| ユニット選択 | クリック | タップ |
| 移動先指定 | クリック（経路プレビュー→確定） | タップ（経路プレビュー→確定ボタン） |
| ダメージ予測 | 敵にホバーで即表示 | 敵をタップで表示 → もう一度タップで攻撃実行 |
| 情報表示 | ホバー | 長押し |
| カメラ移動 | ドラッグ / 端でのスクロール / 方向キー | 1本指ドラッグ |
| ズーム | ホイール / `+` `-` | ピンチ / ダブルタップ |
| 選択解除 | 右クリック / Esc | 空きヘクスをタップ / 戻るボタン |
| ターン終了 | Enter / ボタン | ボタン（未行動ユニットがあれば確認） |
| 未行動ユニット送り | Space | 画面上のボタン |
| アンドゥ | `U` / ボタン | ボタン |

- **移動・攻撃は必ず「プレビュー → 確定」の2段階**にする。誤タップの被害を防ぐ

#### アンドゥとやり直し（詰将棋性の担保）

読んで指すゲームである以上、試行錯誤の手段は必須。
索敵がないため隠された情報が存在せず、**アンドゥで有利な情報を得る抜け穴も存在しない**。
したがって制限を設けず、自ターン内は自由に巻き戻せるようにする。

| 操作 | 可否 |
| --- | --- |
| 自ターン内の移動・攻撃・占領のアンドゥ | **可**。ターン開始時まで何手でも戻せる |
| ターン終了後のアンドゥ | 不可（相手ターンの結果を含むため） |
| マップを最初からやり直す | **常に可**。AI が決定的なので、同じ展開を再現しながら別の手を試せる |

### 7.3 レスポンシブレイアウト

| 画面 | レイアウト |
| --- | --- |
| 横長（PC・タブレット横） | マップ中央 + 情報パネル右 + 操作バー下 |
| 縦長（スマートフォン） | マップを画面の大半に配置 + 下部にボトムシート（選択中ユニット情報・行動ボタン）。詳細は上スワイプで展開 |

- ヘクスの表示サイズは画面幅に応じて可変。初期ズームは「マップ全体が入る」か
  「タップ可能な最小サイズを確保」のうち大きい方
- タップ対象は 44 CSS px 以上を確保。確保できない縮尺ではタップ時に自動でズームインする
- セーフエリア（ノッチ・ホームバー）に対応
- 画面回転・リサイズで再レイアウトし、カメラの注視点は維持する

### 7.4 描画

- Canvas をレイヤ分割: 地形（オフスクリーンにキャッシュ）→ グリッド → ハイライト →
  ユニット → エフェクト → HUD
- `devicePixelRatio` に対応して高解像度端末でもぼやけないようにする
- 描画は**カメラの可視範囲のヘクスのみ**。マップが大きくてもモバイルで性能が落ちない
- アニメーション（移動・被弾・撃破）は `events` を消費するキューで処理し、
  再生中は入力をブロックする。**速度設定とスキップを必ず用意する**
- 低スペック端末向けに「エフェクト簡略化」設定を持つ
- ユニット表現は Phase 2 までは色付きヘクス＋記号のプレースホルダ。
  Phase 7 以降で自作スプライトに差し替え

### 7.5 「読む」ための支援表示

詰将棋性を活かすには、盤面が見えているだけでなく**読める形で提示されている**必要がある。
以下は装飾ではなく機能として優先度を高く扱う。

- **ダメージ予測**: 攻撃前に、与ダメージと自分が受ける返しダメージを**両方とも**確定値で表示する。
  同時解決なので、この2つは常にセットで提示する
- **支援の可視化**: 攻撃時、支援に寄与している味方ヘクスを枠線で示し、
  **それぞれがいくら足しているか**を数値で表示する。借りる量が相手の強さに比例するため、
  「誰が隣にいるか」まで見せないと理解されない
- **包囲の可視化**: 敵ユニットの6ヘクスのうち、埋まっている数を常時表示する。
  **あと1つで包囲成立**という状態は特に強調する。全か無かの効果なので、
  これが見えないと最も重要な一手を逃す
- **敵の移動可能範囲**: 敵ユニットを選ぶと、そのユニットが次ターンに到達できる範囲と
  攻撃できる範囲を表示する。「どこに置けば殴られないか」を読むための最重要機能
- **脅威マップ**: トグルで、敵の攻撃が届くヘクスを重ねて表示する
- **施設の中身**: 各施設をタップすると、中に何が入っているかを表示する
- **熟練度**: ユニット上に階級記章として常時表示し、次のレベルまでの経験値も参照できる。
  ダメージ予測には当然反映する
- **ターン数と勝利条件**: 常時表示する

## 10. テスト戦略

| 種別 | 対象 | 方針 |
| --- | --- | --- |
| 単体テスト | `core/` 全体 | ヘクス幾何、移動コスト、ZOC、戦闘計算、占領、格納・搬出、勝敗判定 |
| ゴールデンテスト | 戦闘計算 | 「攻撃側/防御側/地形/サポート数 → 期待ダメージ」の表をテストデータ化。バランス調整時の意図しない変化を検出 |
| **決定性テスト** | reducer + AI | 同じ初期状態に同じコマンド列を2回流し、最終状態が完全一致することを検証。AI も同一局面で同一の手を返すことを確認する（詰将棋性の生命線） |
| シナリオテスト | reducer | 決まったコマンド列を流し、最終状態を検証（リプレイ機構をそのままテストに使う） |
| 自己対戦 | AI + core | 数百戦を回して例外・無限ループ・膠着を検出 |
| 実機確認 | UI | Phase 2 / 4 / 6 で、スマートフォン実機（縦・横）とタブレットで操作確認 |

CI では `typecheck` → `lint` → `test` → `build` を実行する。

## 12. 検討課題（レビューで決めたい点）

実装前に方針を確定したい項目。**太字が本書としての推奨案**。

### A. プレイテストで微調整するもの

実際に遊ばないと判断できない数値。Phase 4 で通しプレイができるようになった時点で調整する。
初期値だけ置いておき、**JSON でいつでも変えられる状態**にしておくことが実装側の責務。

| パラメータ | 確定値 | 備考 |
| --- | --- | --- |
| `SUPPORT_RATE` | **0.25**（隣接5体で最大 2.25 倍） | 隣接ユニットの力を借りる割合 |
| `ENCIRCLE_MUL` | **0.5** | 包囲されたときの倍率。原作どおり半減 |
| `DAMAGE_SCALE` | **0.6** | 標準的な殴り合いが1回あたり4前後になる値 |
| `COUNTER_COEF` | **0.7** | **原作は対称（係数なし）と思われる。1.0 にする選択肢を残す** |
| 熟練度 `EXP_STEP` / 必要経験値 | 0.10 / 3・8（最大 +20%） | 原作に該当する仕組みがないため本作独自。要調整 |
| `power` / `DEF` / 移動力 / 射程 | 第5.1.1章の表 | **原作データから較正済み** |
| `matchup` の割り当て | 第5.1.1章の表 | 本作独自の追加。値域は5段階に固定済み |

### B. 判断をいただきたいもの

数値は原作データとの照合で確定した。残るのは次の1点のみ。

**数値はすべて確定した。** 反撃係数はバランス調整の範疇として初期値 0.7 のまま進め、
Phase 4 のプレイテストで 1.0（原作同様の対称処理）と比較して決める。

実装着手にあたって残る判断事項はない。

### C. 決定済み（記録）

- **相打ち** — 許容する。同時解決の帰結として、撃破されたユニットも返しダメージを与える。
  「撃破したら返しダメージなし」にすると順次処理に逆戻りするため
- **輸送の展開地形制限** — すべての輸送ユニットに適用する。積荷を降ろせるのは展開可能地形のみ
- **燃料・弾薬の世界観上の説明** — 第1.2章の整理で決着。近未来設定でもあるため、
  細部は新技術で説明できる余地も残る
- **陣営数** — 2陣営固定。3陣営以上はデータ構造上は許容するが UI/AI では対応しない
- **マップサイズ** — 固定しない。カメラがカーソルに追従してスクロールする一般的な方式を採る。
  ミニマップと全体ズームは補助として用意する（必須要件ではない）
- **マップの「解」** — 唯一解は用意しない。攻略法は複数あってよい。
  必須なのは開発者がクリアできることの確認のみ
- **AI の難易度** — 難易度選択は設けず、単一の AI が全マップを担当する
- **工兵** — 不採用。地形改変は導入しない（汎用性がなく死に駒になるため）

## 13. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 数値バランスが煮詰まらない | ゲームとして面白くならない | 全定数を JSON 化。Phase 4 でプレイテスト期間を明示的に確保。自己対戦で定量評価 |
| AI の非決定性が紛れ込む | マップが「解ける問題」でなくなる | 決定性テストを CI に入れる。`Math.random` を ESLint で禁止。反復順に依存しない実装を徹底 |
| AI が弱く、詰将棋として成立しない | 1人用ゲームの手応えが出ない | Phase 4 は成立優先の v1 で通し、Phase 10 で評価関数型に差し替える前提で設計を分離しておく |
| サポート/ZOC がプレイヤーに伝わらない | 戦術が理解されず作業ゲーに見える | サポート数の可視化・敵の移動範囲表示・脅威マップを Phase 7 の必須項目にする |
| 完全情報ゆえに最適手が単調になる | 作業感が出る | 間接砲・輸送・揚陸・潜水艦のように「対処手段が限定される駒」を配置し、手の選択肢を広げる。マップ設計で担保する |
| **死に駒が生まれる** | **「どの場面でも使わないユニットが出ない」という要件を満たせない** | **生産がなく価格で差別化できないため、地形適性・移動力・射程・構造的能力の4軸で差をつける（第5.1章）。各ユニットの `designRole` が埋まらなくなったら設計の失敗と見なす。Phase 9 完了時に全28種の使用率を自己対戦で計測する** |
| 熟練部隊が雪だるま式に強くなる | 序盤の優劣がそのまま決着してしまう | 上限を +20% に抑え、防御力には効かせない。支援と包囲で十分に覆せる範囲に収める |
| 相性を尖らせすぎて詰む場面が出る | 「手駒がないので何もできない」局面が生じる | ATK 表の相性差に 1.8 倍の上限を設ける。攻撃不可（0）は構造的に成立しない組み合わせのみに限定する |
| **航空ユニットが強すぎる** | **陸と海の駆け引きが成立しなくなる** | **航空は3種に絞る。相性の輪（戦車→対空戦車→戦闘機→攻撃機→戦車）で空が一方的に強くならない構造を作る。加えて対空能力を歩兵・駆逐艦・コルベットへ薄く配り、どの編成でも最低限の抵抗ができるようにする。Phase 9 の自己対戦で航空ユニットの勝率寄与を計測する** |
| 重砲が置物になる／強すぎる | 尖らせた駒が機能しない、あるいは支配的になる | 輸送機・揚陸艦で運搬可能にして再展開の道を残す。同時に射線を迂回する経路を必ずマップに用意する |
| モバイルの操作性・性能が確保できない | 「デバイスを問わず」の要件を満たせない | Phase 2 で実機確認を DoD に入れる。可視範囲のみ描画。Phase 6 で最適化を独立フェーズとして確保 |
| スマホ画面にマップが収まらない | 全体戦況が把握できない | ミニマップ／全体ズーム／ボトムシート UI で対処（Phase 6） |
| AI ターンが長い / 見ていて退屈 | 体験の質が落ちる | 探索の深さに上限を設ける。アニメーション速度設定とスキップを必ず用意 |
| ユニット28種の作り込みで停滞 | MVP が遠のく | Phase 4 までは地上8種程度で進め、システム確定後に JSON で追加する |
| 海洋要素が陸戦と噛み合わない | 追加要素が死ぬ | Phase 9 で沿岸マップを専用設計し、「海路が最短の目標」を必ず配置する |
| 素材制作がボトルネック | 見た目が最後まで仮のまま | Phase 7 まではプレースホルダ図形で進行。ロジック完成を優先 |

## 14. 主要な決定の経緯

同じ議論を繰り返さないための記録。

| 論点 | 検討した案 | 決定 | 理由 |
| --- | --- | --- | --- |
| 索敵（Fog of War） | ①なし ②敵ユニットのみ隠す ③未探索を黒塗り | **①なし（原作準拠）** | 情報を隠すと「読み」が「手探り」に変わり、本作の芯である詰将棋性と衝突するため。潜水艦だけは「攻撃できる相手を限定する」ルール（4.5）で表現する |
| 生産 | ①資源制の生産 ②施設に格納された中身のみ | **②中身のみ** | 戦力を有限にすることで一手の重みが増し、マップを問題として設計できる |
| 修理 | ①なし ②施設で回復 | **②施設で回復（+3/ターン）** | 「引いて直すか押し切るか」の判断が生まれ、施設の争奪価値が上がる |
| 戦闘の乱数 | ①なし ②±10% | **①なし** | ダメージ予測を確定値で出せることが詰将棋性の前提 |
| AI の難易度調整 | ①乱数で弱くする ②思考の質で調整 | **②思考の質で調整** | 乱数を入れると決定性が壊れ、マップが解けなくなる |
| アンドゥ | ①不可 ②制限付き ③ターン内は自由 | **③ターン内は自由** | 隠された情報がないため、アンドゥで不当な情報を得る抜け穴が存在しない |
| ユニットの相性 | ①天敵関係を尖らせる ②中庸 ③単純な強弱 | **①を採るが、配置で覆せる範囲に収める** | 相性差の上限を 1.8 倍とし、プレイヤーが操作できる要素（支援2.25×包囲2.00×地形1.40＝6.30倍）が常にそれを大きく上回るようにする |
| ユニットの差別化 | ①価格差 ②地形・機動・射程・能力 | **②のみ** | 生産がないため価格差が存在しない。価格で棲み分ける設計は本作では死に駒を生む |
| 熟練度 | ①なし ②マップ跨ぎで成長 ③マップ内限定 | **③マップ内限定・攻撃力のみ +20% まで** | 各マップが独立した問題であり続ける必要がある。上限を抑えることで雪だるまを防ぐ |
| 特殊能力 | ①数値のみ ②構造的能力まで ③固有アクション | **②構造的能力まで** | 「できる/できない」だけなら読みの複雑さが増えず、役割分担も作れる |
| 占領の所要ターン | ①1ターン ②2ターン | **①1ターン** | テンポ優先。原作準拠 |
| 戦闘の解決順序 | ①攻撃→反撃の順次処理 ②同時解決 | **②同時解決** | ターン制でも1回の戦闘は同時に撃ち合うのが自然。順次処理では先に手を出した側が一方的に得をし、戦闘前の盤面から結果を読みにくくなる |
| 修理の速度 | ①毎ターン +3 ②即時全快 | **②即時全快** | 格納→搬出で2ターンかかる。戦線を離れて戻る移動と併せて十分なコストになっているので、回復量を絞る必要がない |
| 施設ヘクスへの進入 | ①誰でも入れる ②歩兵系のみ（未占領時） | **②歩兵系のみ** | 施設の争奪を必ず歩兵の仕事にする。出口を塞いで搬出を止める戦術も生まれる |
| AI の難易度 | ①3段階 ②単一 | **②単一** | 手応えの差はマップ設計で作る。難易度ごとに解法が変わると調整対象が3倍になる |
| 工兵と地形改変 | ①採用 ②不採用 | **②不採用** | 汎用性がなく死に駒になりやすい。地形を書き換えられるとマップを問題として設計できなくなる |
| 輸送ユニットの構成 | ①武装/非武装で2種 ②1種に統合 | **②1種に統合** | 武装の有無だけでは差別化にならない。空輸は別枠（輸送機）で役割を分ける |
| 相打ち | ①撃破したら返しダメージなし ②許容 | **②許容** | ①にすると同時解決が崩れて順次処理に逆戻りする。返しダメージは戦闘前の戦力に比例するため、弱った敵を倒すときの被害は元々小さい |
| 重砲の位置づけ | ①低速の間接砲 ②移動力ゼロ | **②移動力ゼロ** | 中途半端に遅いだけでは自走砲の下位互換になる。動けないという極端な制約が、他と重ならない性格を作る |
| 対空のバリエーション | ①専用を1種に絞る ②近接と間接を1体ずつ揃える | **②近接と間接を1体ずつ** | 1種に絞ると間接兵器の駆け引きが対空から失われる。対空戦車が地上攻撃力も持つことで「戦車→対空戦車→戦闘機→攻撃機→戦車」の相性の輪が閉じ、どの駒も万能にならない |
| 地雷の実装形式 | ①地形として置く ②ユニットとして扱う | **②ユニット** | 移動力0・攻撃力0のユニットにすれば、「敵ユニットのいるヘクスは通過不可」「輸送の積載・展開」という既存ルールの組み合わせだけで成立する。原作の挙動にも近い |
| 航空ユニットの数 | ①ヘリ・爆撃機・無人機を含め6種 ②3種 | **②3種** | 空は陸にも海にも強い。種類を増やすと抑止が難しくなり、駒同士の差別化も苦しくなる |
| 無人機 | ①航空ユニットとして追加 ②見送り | **②見送り** | 無人兵器は地上兵器として扱うほうが素直。航空をこれ以上増やさない方針とも整合する（第5.1.3章に案として保持） |
| バギーの位置づけ | ①既存の駒で代替できる ②移動中攻撃を持つ別の駒 | **②別の駒として追加** | バギーの核は「移動中の任意地点で攻撃できる」点で、他のどの駒でも代替できない。間接砲の「移動したら撃てない」制約のちょうど裏返しになっており、撃ってから逃げるという別軸を作る |
| ZOC の書き方 | ①進入したら移動終了 ②ZOC ヘクスへの連続進入を禁止 | **②連続進入の禁止** | 密な戦線は ZOC ヘクスが連続するため貫通できず防御力は保たれ、単独の敵の脇をかすめる迂回だけが許される |
| バギーの行動モデル | ①攻撃してから移動 ②移動してから攻撃 ③移動中の任意地点で攻撃 | **③移動中の任意地点で攻撃** | 移動と攻撃が一続きの行動であり、開始位置で撃ってから全力で動くことも、動いてから撃つこともできる。残 MP がなければ攻撃後に動けないという制約も自然に導かれる |
| 攻撃後移動と ZOC の関係 | ①ZOC を無視する ②攻撃で移動区間が切れ判定がリセットされる | **②区間ごとに判定** | ①だとバギーが ZOC から自由になりすぎる。②なら「ZOC ヘクスを通過できるのは1区間につき1つ」という一貫した規則のまま、バギーだけが1ターンで2つ通過できる。これが「攻撃を足がかりに敵陣の裏へ回り込む」というバギー本来の役割を作る |
| `hover` 移動タイプ | ①水陸両用の駒を足す ②移動タイプごと削除 | **②削除** | 浅瀬は地上ユニットが高コストで進入できるようにすれば足りる。専用の移動タイプを設ける理由がなかった |
| 支援と包囲の関係 | ①1つの補正にまとめる ②原作どおり別々の仕組みにする | **②別々の仕組み** | 原作では、支援は「隣接する自軍の力を強さに比例して借りる」、包囲は「相手の6ヘクスをすべて埋めると攻防が半減する」という別物だった。見る場所（自分の隣／相手の周囲）も、効き方（連続的／全か無か）も違う |
| 支援の量 | ①隣接数に応じた一律の割合 ②支援側の能力値に比例 | **②能力値に比例** | 一律だと「隣に何体いるか」しか問われない。比例させることで「どの駒を隣に置くか」が問われるようになり、重装戦車は盾に、突撃戦車は矛になる |
| 包囲の判定 | ①隣接数に応じて段階的 ②6ヘクスすべてで発動 | **②全か無か** | 原作の挙動。最後の1ヘクスを埋められるかで結果が劇的に変わるため、捨て身で駒をねじ込む判断が生まれる |
| 包囲と地形・盤端 | ①ユニットで埋めた分だけ数える ②進入不可地形と盤外も「埋まっている」と見なす | **②地形も数える** | 包囲とは逃げ場のない状態を指す。逃げられない方向を塞ぐ必要はない。結果として「敵を山や海に押し付けてから包囲する」という手が生まれる |
| 地形コスト表 | ①ユニット説明で個別に書く ②表として一元定義 | **②一元定義（第5.2章）** | 第16版まで表を定義しないままユニット説明に「森林に入れない」等と書いており、裏付けがなかった。地形×移動タイプの表を唯一の根拠とし、説明文はそこから導く |
| 重戦車系の地形制限 | ①ユニットごとの例外 ②専用の移動タイプ ③移動力から自動的に決まる | **③移動力から導く** | 重戦車が悪路に入れないのは装甲のせいではなく、移動力が足りないから。`移動コスト > 総移動力なら進入不可` という一般則だけで済み、移動タイプも例外規定も増やさずに表現できる |
| 山岳への進入 | ①移動力が足りれば戦車も登れる ②徒歩系のみ | **②徒歩系のみ** | 車両が山に登れるのはおかしい。車両（track）の上限は荒地、タイヤ（wheel）は丘陵まで。山岳は歩兵と多脚戦車だけの領域になり、装甲が絶対に来られない場所ができる |
| タイヤ系の範囲 | ①軽車両全般 ②バイク兵・輸送車・ロケット砲・ミサイル車のみ | **②限定する** | 原作でタイヤだったのは輸送車とバイクのみで、バギーは戦車と同じ移動タイプだった。バギーをタイヤにすると平地で鈍って道路で伸びすぎるという歪みが出る |
| 移動タイプの数 | ①9種（bike・heavy・walker を含む） ②6種 | **②6種に削減** | バイク兵が悪路に弱いのはタイヤだからで、バギーなど他のタイヤ車両と同じ性質。多脚戦車は徒歩と同じ扱いで足りる。重戦車の制限は移動力から導かれる。タイプを増やす理由がどれも無かった |
| 地形効果の粒度 | ①耐性クラスごとに値を持つ ②地形ごとに1つの値 | **②1つの値** | 原作は移動コストと地形効果が同じ順序で上がる単純な階段構造だった。クラス別の値は複雑さに見合う効果がない |
| 1.0 未満の地形効果 | ①橋や浅瀬で被害を増やす ②設けない | **②設けない** | マイナス倍率は理解の負荷を増やすだけだった。地形は守るか何もしないかのどちらか |
| 航空機の対潜攻撃 | ①攻撃機に対潜能力を持たせる ②駆逐艦のみ | **②駆逐艦のみ** | 攻撃機が潜水艦を撃てると、「対潜の駒をどこに置くか」という問題が制空権を取るだけで解けてしまう。回答を1種に絞ることで艦隊編成そのものが問われる |
| 地雷の扱い | ①ZOC も支援も持たない特例 ②他のユニットと同じ | **②特例を設けない** | 原作では地雷を狙われやすい戦車の隣に置いて硬くする防衛戦術があった。地雷の DEF 5.00 が支援としてそのまま効くことで、これが自然に成立する |
| 攻撃力の表現方法 | ①1つの ATK 表 ②対地/対空の2値 × matchup | **②原作と同じく対地・対空を分離** | 原作は対地と対空を独立した2値で持っていた。対空車両シーカーは対地30/対空65で比が2.2倍あり、相性の1.64倍上限では表現できない |
| 能力値の決め方 | ①独自に設計 ②原作データから較正 | **②原作から較正** | power は原作攻撃力の 1/5、DEF は原作防御力 D を 100÷(100−D) で除数化。被ダメージの比率が原作と一致する |
| 軽装甲車 | ①残す ②削除 | **②削除** | 原作のラビット（バギー）は対地70でグリズリー並みの火力を持つ。これを反映するとバギーが軽装甲車の完全な上位互換になり、軽装甲車が死に駒になる |
| 防御力の扱い | ①原作同様の減衰率（％）で加算 ②除数として除算 | **②除数** | ①は地形とサポートを足すと 100% に届き無敵が成立する。原作では防御80のユニットが丘陵に登るだけで無敵になり、ハメ手として機能していた。除算にしたうえでダメージ下限を1とすることで、無敵になる組み合わせを原理的に排除する |
| 要塞戦車の対空 | ①対空を持たせない ②持たせる（輪の外に置く） | **②持たせる** | 対空を持つ戦車は「攻撃機→戦車」を壊すが、要塞戦車は移動力2で開けた地形しか進めないため、答えが「間接砲で崩す」か「迂回する」に移るだけで済む。輪を壊すのではなく、攻城戦という別種の問題を盤上に置く駒として扱う |
| 戦車のバリエーション | ①3種 ②6種に拡張 | **②6種** | 原作は戦車だけで7種と分厚い。主力戦車を基準に、1つの能力を上げたら別の1つを下げる形で4種を派生させ、どれも基準の上位互換にならないようにした |
| 原作の CPU 優遇ユニット | ①取り込む ②取り込まない | **②取り込まない** | モンスター型（全能力が高い重戦車）は他戦車の上位互換になり死に駒を生む。ハンター型（陸空両対応の戦車）は「攻撃機→戦車」の関係を壊し相性の輪が閉じなくなる。本作の AI は決定的で先読みするため、AI を強く見せるための優遇ユニットを必要としない |
| 地雷 | ①案として保留 ②採用 | **②採用** | 移動力0・攻撃力0のユニットとして、既存ルールの組み合わせだけで成立する |
| クリア目標の☆評価 | ①入れる ②入れない | **②入れない（現時点では）** | バランス調整の変数が増えすぎる。マップが揃う Phase 10 で改めて検討する |
