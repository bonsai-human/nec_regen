# 実装で判明した仕様の食い違いと、暫定の解釈

実装計画書は版を重ねているため、章によって記述が食い違っている箇所がある。
Phase 1（コアモデル）の実装にあたって解釈が必要だったものを、
**採った解釈とその根拠**とともに記録する。

計画書を更新するか、別の解釈を採るかは判断をいただきたい。
いずれも `data/*.json` の値かローダの分岐を変えるだけで済むよう作ってある。

**1 と 2 は確認済み**（2026-08-15）。実装計画書の該当箇所も更新した。

---

## 1. バイク兵は占領できるか ✅ 確定

**結論: 占領できる。** 占領できるのは歩兵・重歩兵・バイク兵の3種。

| 出典 | 記述 |
| --- | --- |
| 第0章・第4.6章 | 占領できるのは**歩兵・重歩兵のみ** |
| 第5.1章（地上表） | バイク兵の唯一の役割 = 「道路の上でだけ異常に速い**占領要員**」 |
| 第5.1章（歩兵とバイク兵） | 「**占領できる駒は3種あり**、地形との関係がそれぞれ正反対」 |

根拠:

- バイク兵の耐性クラスは `infantry` なので、第4.6章の「歩兵系」に含まれると読める
- 占領できないとバイク兵の「唯一の役割」欄が空になり、設計制約2に反する
  （火力2・防御1.10の駒に、占領以外の仕事が残らない）

→ `data/units.json` で3種に `canCapture: true` を設定。

## 2. 潜水艦は潜水艦を攻撃できるか ✅ 確定

**結論: 攻撃できる。** 対潜手段を持つのは駆逐艦と潜水艦。

| 出典 | 記述 |
| --- | --- |
| 第4.5章 | `canDetectSub: true` を持つのは駆逐艦のみ。**他のいかなるユニットも潜水艦を攻撃できない** |
| 第5.1.1章（海上表） | 潜水艦の対潜相性が △（0.85）と定義されている |

第5.1.1章の表が潜水艦に対潜相性 △ を与えているとおり、**潜水艦同士は撃ち合える**。
`data/units.json` で潜水艦にも `canDetectSub: true` を設定した。

水上艦から見た「潜水艦への回答は駆逐艦だけ」という第4.5章の設計意図はそのまま保たれる。
変わるのは潜水艦を潜水艦で狩れるようになる点だけで、相性は
駆逐艦 ◎1.15 に対し潜水艦 △0.85 なので、**対潜の主役は駆逐艦のまま**になっている。

なお、マップ検証の「潜水艦に対する回答があるか」は `canDetectSub` を見ているため、
相手陣営が潜水艦だけを持つマップも通るようになる。

## 3. 間接兵器の射程

| ユニット | 第5.1章の能力値表 | 別の箇所の記述 | 原作データ |
| --- | --- | --- | --- |
| 重砲 | 2〜6 | 2〜8（第5.1章「間接砲4種」） | モノケロス 6 |
| ロケット砲 | 2〜5 | 3〜6（同上） | ナスホルン 5 |
| 対空ミサイル車 | 2〜5 | 2〜4（第5.1章「対空は近接と間接」） | ホークアイ 5 |
| 自走砲 | 2〜4 | 2〜4 | エストール 4 |

**採った解釈: 第5.1章の能力値表（原作の射程と一致する側）。**

第5.1.2章の原作データと突き合わせると、能力値表の最大射程は原作の射程と完全に一致する。
散文側の数値は較正前の版の名残と判断した。

## 4. 輸送ユニットが積荷を降ろせる地形

| 出典 | 記述 |
| --- | --- |
| 第4.7章の表 | 装甲兵員輸送車は「平地・道路・**荒地**・砂浜」に降ろせる |
| 第4.7章の共通ルール | 降ろせるのは**段階0と段階1のみ**（道路・橋・施設・平地・砂浜）。**すべての輸送ユニットに共通** |

**採った解釈: 共通ルール（段階0と1のみ）。**

共通ルール側が「すべての輸送ユニットに共通する制約」と明示しているため。
荒地は段階3なので対象外になる。展開地形はユニット個別のデータとしては持たせず、
地形の段階から判定する形にした（Phase 9 の輸送実装時に確定）。

## 5. 重装戦車の「橋と湿地に入れない」

第5.1章の「差別化の軸」の例に *重装戦車は橋と湿地に入れない* とあるが、
第4.3章は **「進入できるかどうかは2つのルールだけで決まる」「ユニットごとの個別制限は設けない」**
と明記している。橋は段階0・湿地は段階3で、track / 移動力4の重装戦車はどちらにも入れる。

**採った解釈: 第4.3章（地形コスト表だけで判定）。** 個別制限は実装していない。

## Phase 4（戦闘）で判明したこと

### 第5.1.1章の検証表で、攻撃機の2行だけ matchup が抜けている

「相性の輪が成立していることの確認」の表は、ほとんどの行で `matchup` を掛けている
（例: 潜水艦 → コルベット を `16.1 = 14 × 1.15` と計算）。
一方、攻撃機の2行だけ素の `power.ground = 14` で計算されている。

| 対戦 | 計画書 | 式どおり |
| --- | --- | --- |
| 攻撃機 → 主力戦車 | 14 ÷ 1.65 × 0.6 = 5.1 | 16.1 ÷ 1.65 × 0.6 = **5.9** |
| 攻撃機 → 対空戦車 | 14 ÷ 1.45 × 0.6 = 5.8 | 16.1 ÷ 1.45 × 0.6 = **6.7** |

**実装は式どおり**（matchup を掛ける）。相性の輪の向きは変わらないが、
「攻撃機 ⇔ 対空戦車は互角」という狙いからは少しずれて、攻撃機が有利になる
（与7 / 返し4）。反撃係数を 1.0 にすると 与7 / 返し5 で狙いに近づく。
第12章Bの「反撃係数を 0.7 か 1.0 か」の判断材料として記録しておく。

### 盤の端は包囲されやすい

包囲判定は盤外のヘクスを「埋まっている」と見なすため、
**盤の縁にいる駒は少ない駒数で包囲が成立する**（角なら2〜3体）。
仕様どおりの帰結だが、マップ設計では「縁に追い詰める」筋が強いことになる。

### 自己対戦の結果（バランスの初期値）

同梱マップ `map01_crossroads` で AI 同士を戦わせると、
**19ターンで青軍（後手）が全滅勝ち**。中立工場4つをすべて青が取っている。
貪欲 AI 同士では後手が有利に出る。先手勝率 45〜55% はフェーズ10の目標なので、
現時点では記録のみ。

## 実装側で決めたこと（計画書に記載がなかったもの）

### 戦力価値 `value`

計画書には主力戦車の 400 という例しかないため、**残り27種は暫定値**。
役割と能力から目分量で割り当て、50 刻みに丸めてある。
AI 評価（第6章）とマップ設計に効く値なので、Phase 10 のバランス調整で見直す。

### `cargo` の表現

計画書の `cargo: { capacity, allow: [] }`（配列）では、輸送機の
**「歩兵2 **または** 車両1」** を表現できない。
そこで `allow` を「耐性クラス → 消費する積載枠」の対応表に一般化した。

```jsonc
"cargo": { "capacity": 2, "allow": { "infantry": 1, "light": 2, "armor": 2 } }
```

装甲兵員輸送車は `{ capacity: 2, allow: { infantry: 1 } }`、
揚陸艦は `{ capacity: 3, allow: { infantry: 1, light: 1, armor: 1 } }` で、
第4.7章の表をそのまま表せている。

### 自軍が占領済みの施設ヘクスには誰でも入れる

第4.6章は「**未占領**の施設ヘクスには占領できるユニットしか進入できない」と
「自軍の施設ヘクスには**対応する種別**のユニットが進入できる（修理のため）」を並べている。
後者を「対応しない種別は進入できない」と読むと、自軍の港に戦車が立てなくなる。

実装では**進入制限は未占領の施設だけ**とし、自軍施設へは地形が許す限り誰でも入れる。
施設の種別（工場＝地上、港＝海上、飛行場＝航空）は、修理を受けられるかどうかの
判定にだけ使う（Phase 4 で実装）。

### ターンの数え方

`turn` は**全陣営が1回ずつ手番を終えると1つ進む**（2陣営なら1ターン＝赤と青の各1手番）。
増援の出現間隔とターン制限もこの数え方を基準にする。
「間隔3の工場」は3ターンに1回、つまり赤と青が3回ずつ動くごとに1体出す。

### 最初のマップを陸戦マップにした

第5.3章の例は `map01_coastal`（沿岸マップ）だが、海上ユニットと揚陸は
第9フェーズの範囲にあり、MVP（Phase 4）では遊べない。
そこで最初のマップは**河川と2本の橋を持つ陸戦マップ** `map01_crossroads` とし、
沿岸マップは Phase 9 で追加する。海・港・浅瀬のデータ定義と検証は済んでいるので、
マップ JSON を足すだけで動く状態にしてある。
